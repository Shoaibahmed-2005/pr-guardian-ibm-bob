# How IBM Bob IDE and watsonx.ai Power PR Guardian

## IBM Bob IDE: The Development Engine

PR Guardian was built entirely using **IBM Bob IDE** as the primary development tool, demonstrating the power of AI-assisted software engineering. Over the course of 2.5 hours, Bob IDE was used to plan, architect, and generate all **3,429 lines of production code and documentation** across 22 files.

The development process began with Bob in **Plan Mode**, where it analyzed the hackathon requirements and created a comprehensive project architecture. Bob designed the folder structure, planned the dual integration strategy (MCP Server + Custom Mode), and mapped out the complete technology stack. This planning phase produced detailed architecture diagrams, workflow documentation, and AGENTS.md files that guided the entire implementation.

Switching to **Code Mode**, Bob generated the complete codebase file-by-file. This included the GitHub API client (310 lines with caching and retry logic), the AI analyzer (429 lines supporting three AI providers), the MCP server implementation (298 lines with stdio transport), the CLI with rich terminal UI (398 lines), and all configuration, logging, and utility modules. Bob didn't just write code—it implemented production-ready features like exponential backoff retry, TTL-based caching, graceful error handling, and multi-method JSON parsing.

Bob also created the **MCP Server integration** that allows Bob IDE itself to call PR Guardian tools programmatically. This meta-integration means Bob can use PR Guardian to review code, creating a powerful feedback loop where the AI that built the tool can also use it. The MCP server exposes three tools (review_pr, check_security, get_release_notes) that Bob invokes via the Model Context Protocol.

Additionally, Bob designed the **Custom Mode definition** (.bob/modes/pr-guardian.md) that transforms Bob into a specialized security-focused code reviewer. This 425-line mode file includes the system prompt, security check patterns, suggested commands, and example interactions—all generated by Bob to extend Bob's own capabilities.

## IBM watsonx.ai: The Intelligence Core

At the heart of PR Guardian's analysis engine is **IBM watsonx.ai**, specifically the **Granite-3-8B-Instruct model**. This model was chosen for its exceptional performance in code understanding, security vulnerability detection, and structured output generation.

The integration with watsonx.ai demonstrates enterprise-grade IBM Cloud usage. PR Guardian implements **IAM token-based authentication**, making POST requests to `https://iam.cloud.ibm.com/identity/token` to obtain bearer tokens, which are then cached for 50 minutes to optimize performance. These tokens authenticate requests to the watsonx.ai endpoint at `https://us-south.ml.cloud.ibm.com/ml/v1/text/generation`.

The Granite model receives carefully engineered prompts that include PR metadata (title, author, branches, file counts) and code diffs (up to 8,000 characters). It analyzes the code across four dimensions—security, bugs, missing tests, and code quality—returning structured JSON with severity levels, descriptions, actionable suggestions, and line numbers. The model's parameters are tuned for code analysis: greedy decoding for deterministic results, 1,000 max tokens for comprehensive findings, and temperature 0.3 for focused, technical responses.

PR Guardian's robust JSON parsing handles Granite's responses through three fallback methods: direct parsing, regex extraction, and bracket extraction. This ensures reliable operation even when the model includes explanatory text alongside the JSON output.

The combination of IBM Bob IDE (for development) and IBM watsonx.ai Granite (for analysis) creates a complete IBM technology showcase: Bob built the tool, and Granite powers it. This demonstrates the full potential of IBM's AI ecosystem for modern software development.
